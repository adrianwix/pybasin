# TorchFeatureExtractor supported-feature checklist

`TorchFeatureExtractor` (`packages/tstorch/src/tstorch/torch_feature_extractor.py`) merges
one `dict[str, FeatureFactory]` per calculator file into `SUPPORTED_FEATURE_FACTORIES`. See
`tstorch/feature_factory.py` for the mechanism and `references/performance-notes.md` for why
it's shaped the way it is. This file is a checklist only — what's wired in. Numbers are never
recorded here or anywhere else by hand: `packages/tstorch/reports/report.md` (regenerated by
`scripts/benchmark/benchmark-feature.sh --match <domain>/<feature>`, parsed straight from
pytest-benchmark's own JSON, upserted per feature so re-running one doesn't erase another) is
the only source of truth for current numbers. See `performance-notes.md` for why.

Source of truth: `SUPPORTED_FEATURE_FACTORIES` itself, if this list drifts.

Per-feature migration history (bugs found, design decisions) lives in
`migration-logs/<domain>.md` files, one per calculator file - this file itself stays
a pure checklist.

### `torch_features_autocorrelation.py` — migrated to `Feature` classes, wired into `SUPPORTED_FEATURES`

No `DEPRECATED_FeatureFactory` dict remains in this file - every feature below explicitly
inherits `Feature[ParamsT]` (all four take parameters), constructed directly by
`SUPPORTED_FEATURES[name]` and by direct callers alike.

- [x] `Autocorrelation` (`autocorrelation`) — parametrized (`lag`), shared direct-sum/FFT
      kernel, keyed on distinct-lag *count* rather than max lag (so a single-lag request
      costs the same as computing that lag alone) - see `migration-logs/autocorrelation.md`
      for why an earlier standalone, single-lag-only version was wrong, not just slower.
- [x] `PartialAutocorrelation` (`partial_autocorrelation`) — parametrized (`lag`), shared
      Durbin-Levinson kernel; a single requested lag costs the same as every order up to it
      (the recursion is inherently sequential), so there is no separate single-lag fast path
      to lose by sharing.
- [x] `AggAutocorrelation` (`agg_autocorrelation`) — parametrized (`maxlag`, `f_agg`), this
      codebase's architecture reference (see `references/api-design.md`); shared
      direct-sum/FFT ACF kernel, masked per request.
- [x] `AutocorrelationPeriodicity` (`autocorrelation_periodicity`) — parametrized (`output`,
      plus structural `min_lag`/`peak_threshold`), grouped-shared-core kernel (both
      `strength`/`period` are already computed from one peak search).

Timing: `packages/tstorch/reports/report.md` (regenerate with
`scripts/benchmark/benchmark-feature.sh --match autocorrelation/<feature>`). Row meanings and
caveats (compile-cost-vs-steady-state, tsfresh parallelism fairness, GPU noise) are in
`performance-notes.md`, not repeated here.

See `migration-logs/autocorrelation.md` for the bugs found and design decisions during
migration - including the `agg_autocorrelation` NaN-vs-0 bug found while adding 8-value param
coverage during the `Feature`-class migration.

### `torch_features_entropy_complexity.py` - migrated to `Feature` classes, wired into `SUPPORTED_FEATURES`

- [x] `permutation_entropy` (`tau`, `dimension`) — parametrized, padded windows
      broadcast both structural parameters through one kernel.
- [x] `binned_entropy` (`max_bins`) — parametrized, shared min/max + per-bin-count
      `searchsorted` kernel (`_binned_entropy_multi`).
- [x] `fourier_entropy` (`bins`) — parametrized, shares `welch_psd` once across every
      requested bin count and delegates the rest to `_binned_entropy_multi`.
- [x] `cid_ce` (`normalize`) — parametrized, Type A shared kernel (`ce`/`std` computed
      once, `torch.where` selects per requested column).
- [x] `approximate_entropy` (`m`, `r`) — parametrized, running distance passes
      broadcast every structural window length and tolerance.
- [x] `sample_entropy` — parameter-free, same O(T²) Chebyshev-distance shape as
      `approximate_entropy`.
- [x] `lempel_ziv_complexity` (`bins`) — parametrized, broadcasts symbolization and
      parses the flattened batch/state/parameter rows through a registered operator.

See `migration-logs/entropy_complexity.md` for the bugs found and design decisions
during migration.

Timing: `packages/tstorch/reports/report.md` (regenerate with
`scripts/benchmark/benchmark-feature.sh --match entropy_complexity/<feature>` per feature).
`approximate_entropy`/`sample_entropy`'s tsfresh reference calls are themselves O(T²), so a
full-domain `--match entropy_complexity` run takes several minutes (dominated by tsfresh's
own single-feature benchmark on the longer cached trajectories, not tstorch's).
