# ExecuTorch Basic Statistics Experiment

Goal: test whether the same configured `TorchFeatureExtractor` plan can be exported through
PyTorch's edge stack for users who want PyTorch-managed deployment on mobile, embedded, or
microcontroller-oriented targets.

Official docs:

- ExecuTorch: https://docs.pytorch.org/executorch/stable/index.html
- PyTorch Edge overview: https://docs.pytorch.org/get-started/executorch/

## Target Question

Can this API:

```python
TorchFeatureExtractor(
    features={"mean": None, "maximum": None, "minimum": None},
    normalize=False,
    use_compile=False,
)
```

lower to an ExecuTorch artifact without changing the user's feature-selection API?

## Baseline

Use the same combined basic-statistics plan as `aoti_basic_stats`:

- input: `(B, S, T)` float32
- features: `mean`, `maximum`, `minimum`
- combined output: `(B, S, 3)` for the generated kernel, or `(B, S * 3)` when routed through
  `extract_features`

## Current Result

The Python 3.12 ExecuTorch 1.3 wheel can lower the generated `TorchFeatureExtractor` kernel:

1. Build the internal `TorchFeatureExtractor` plan.
2. Wrap the generated kernel in an `nn.Module`.
3. Export with `torch.export.export`.
4. Lower with `executorch.exir.to_edge(...).to_executorch()`.
5. Save the `.pte` buffer.
6. Execute it through the C++ runtime symbols exposed by the pip wheel's `_portable_lib`
   extension.

The generated `.pte` for `(mean, maximum, minimum)` is about 2 KB and supports dynamic batch
sizes from 1 to 10000 when exported with a non-singleton example batch.

In this environment, importing the ExecuTorch 1.3 Python runtime binding fails because
`_portable_lib` has an unresolved C10 symbol. The C++ runner can still link against the same
shared object with unresolved shared-library symbols allowed, but this is a pip-wheel runtime
experiment, not a clean embedded runtime package.

The pip-wheel runtime still links against LibTorch and the installed PyTorch CUDA libraries. That
makes it inappropriate as the tiny deployment story for ESP32-class targets. The standalone
codegen experiment remains the small-runtime path.

Run:

```bash
PYTHONPATH=packages/tstorch/src UV_CACHE_DIR=/tmp/uv-cache uv run python \
  packages/tstorch/experiments/exporting/executorch_basic_stats/run_executorch_basic_stats.py
```

The consolidated comparison is generated by:

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run python \
  packages/tstorch/experiments/exporting/run_basic_stats_report.py
```

## Constraints

This experiment should not add ExecuTorch as a core tstorch dependency. Keep it optional and
isolated under `experiments/` until the packaging story is clear.
